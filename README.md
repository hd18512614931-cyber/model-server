## 项目定位

项目以佛山木版年画为主题，不只展示一张 AI 图片，而是继续解释一张年画如何经过分版、上色和逐层套印形成最终画面。

核心体验包括：

- 了解佛山木版年画的历史、工具与制作工艺。
- 输入主题并生成具有年画视觉特征的 AI 图片。
- 将生成结果拆分为多个透明色彩图层。
- 通过拖纸、压印和图层叠加模拟传统套印过程。
- 在 2D 页面查看分色图层，在 3D 展厅查看相关模型与内容。

## 技术亮点

### 1. AI 结果不是终点

普通 AI 生图项目往往在“得到一张图片”后结束。本项目继续把图片转换为可解释的制作过程：分析主要颜色、生成独立色版，再由小程序逐层叠加展示。

### 2. 套印交互

用户选择木板后拖动纸张完成压印。每一次操作只增加对应色版，让最终画面从黑线骨架逐步形成完整年画。

当前演示色版包括：

- 黑色：线稿、轮廓与细节。
- 红色：主体红底与红色色块。
- 黄色：明亮装饰色。
- 深黄色：文字、边框与木纹等厚重色。
- 蓝色：蓝色与青蓝色块。

### 3. 小程序工程化

- 主包启用了按需注入，较重的 AI、分色和 3D 页面使用分包。
- 静态资源逐步迁移到 CloudBase，降低小程序代码包体积。
- `project.private.config.json`、本地依赖和敏感信息不进入仓库。
- GitHub Actions 用于资源同步和工程流程标准化。

## 已知边界

- 首页包含全屏背景视频、音频、多个章节和大量交互内容，冷启动时首屏可能出现等待或卡顿。
- 当前代码在 `onLoad` 阶段会解析背景媒体地址并预加载刀具图片，增加了首次进入时的网络与渲染压力。
- 拖纸等连续触摸交互中存在高频 `setData`，部分设备上可能产生掉帧。
- AI 生图、云文件和 3D 能力依赖外部服务与云端资源，服务状态会影响体验。
- 当前仓库尚未同步最后一次线上发布使用的全部源文件。

这些问题会作为作品集收尾项处理，但不会为了展示用途重新设计整个产品。

## 收尾优化范围

只处理对第一次体验和作品展示最明显的问题：

1. 首屏先显示轻量静态画面，背景视频在首屏稳定后再加载。
2. 刀具图片不再在 `onLoad` 全部预取，进入对应章节时再按需加载。
3. 为拖纸交互增加节流，减少连续 `setData` 带来的卡顿。
4. 补充网络超时、媒体失败和云服务异常的友好兜底。
5. 使用真实设备完成一次完整路径验收，并录制 10–20 秒无剪辑功能实录。
6. 将微信开发者工具中的实际发布源码与本仓库做差异比较后同步。

## 源码同步说明

